Updated 2026-10-12 (R1b part 2 - HTTP/2).

## Setup
- Rust proxy: `ferrotap_proxy` (hudsucker 0.25 with `http2` feature, rcgen 0.14, rustls 0.23), listening on 127.0.0.1:8897. It writes `sessions.json` when `FERROTAP_SESSIONS_DUMP=1` is set (off by default).
- Rust CA: a project-local CA generated by rcgen.

- Origin / test target: `https://nghttp2.org/httpbin/get`.

### 2. 5,000-Request Benchmark & RAM Footprint
Load: 5,000 plain-HTTP GETs (200-byte body), 20 concurrent workers, local origin on port 8895. Both proxies were already running (not relaunched). Python was measured second (warmer machine).

| Metric | Rust 8897 | Python 8899 |

### 3. Findings & Performance Analysis
- **RAM Footprint**: Rust achieves a ~38% lower idle working set (21.9 MB vs 35.4 MB) and ~40% lower peak working set (42.7 MB vs 71.5 MB). Memory stability is confirmed with 0 errors over 5,000 requests.
- **Throughput / Latency**: Rust in debug mode achieved 25.1 req/s compared to Python's 675.7 req/s (~27x slower).
- **Bottleneck Analysis**:
  1. The Rust proxy binary was running a debug build (`target_ws\debug\ferrotap_proxy.exe`), lacking compiler optimizations.
  2. The Rust session recorder performs synchronous full file rewrites of `sessions.json` on each response, yielding O(N^2) disk I/O scaling over 5,000 requests.
- **Action Items Before Final Sign-off**:
  1. Compile release binary: `cargo build --release`.
  2. Implement append-only or batched session writing for `sessions.json`.
  3. Re-benchmark release build to establish true throughput parity.

## Final Verdict (R1b Part 4)
- **Functional Parity**: VERIFIED. Full re-run of HTTP/1.1, HTTPS MITM, HTTP/2 (`h2_client.py` & `compare_sessions.py`), and WebSocket frames (`compare_ws.py`) confirms 100% parity against Python baseline.
- **RAM Efficiency**: VERIFIED. Rust achieves ~40% working set reduction compared to Python baseline under identical load.
- **Throughput Performance**: NOT ACCEPTED pending release mode build and batched I/O optimizations.

## Results (Release Speed Optimization & Benchmark + RAM - R1c)

### 2. Analysis & Verdict
- **Throughput & Latency**: Rust release build achieved 6,489.7 req/s and 2.7 ms p50 latency vs Python's 724.9 req/s and 26.3 ms p50 latency (~9x faster throughput, ~10x lower latency), fully satisfying the requirement of matching / exceeding Python within 2x.

- **Optimizations Applied**: `--release` compiler profile, per-host leaf certificate caching via `RcgenAuthority`, upstream client connection pooling (`pool_max_idle_per_host(64)`, `pool_idle_timeout(90s)`), and dirty-flag batched disk flushing for `sessions.json`.
- **Verdict**: R1c speed optimization verified and accepted.
