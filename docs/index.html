See exactly what your apps send.

Ferrotap is a local HTTP/HTTPS debugging proxy. Capture and inspect every request and response, pause and edit them with breakpoints, rewrite traffic with rules, replay and compose from scratch, and even open packet captures — in one desktop app, with nothing leaving your computer.

No account, no cloud, no telemetry. Your traffic stays on your device.

What it does

Capture & inspect

A live grid of requests with a rich inspector: headers, query & form params, cookies, raw view, pretty JSON (JSONP/NDJSON aware), XML/HTML, JavaScript, a hex view, and inline image preview for both requests and responses.

Decode HTTPS

Decrypt TLS using a root certificate Ferrotap generates locally, just for your install — never a shared key. Inspect encrypted traffic the same as plain HTTP.

Powerful filters

Filter the grid with simple keys (host:, status:5xx, size:>100000, -host:ads) or a full mitmproxy-style expression language (~m POST & ~c 5xx). Packet captures use a Wireshark-style syntax.

Breakpoints

Pause a request or response and edit it before it continues. Target them with the same expression language — method, URL, host, status, headers, content-type and body (~s & ~t json).

Auto-responder & rewrite

Map URLs to local files or other hosts, serve canned responses, rewrite headers and bodies, and throttle bandwidth. Match by contains, glob (*/api/*) or regex, plus header / cookie / body / status conditions.

Compose & replay

Build and resend requests, organize them into collections with environment variables, and assert on the responses. Paste a curl command to import it, or copy any session as cURL, HTTPie, wget, PowerShell, Python, fetch, C#, Go or Rust.

Packet captures

Open and save .pcap / .pcapng, decode protocols, follow a TCP stream, and browse conversations, endpoints and an I/O graph — a built-in lightweight packet view.

WebSocket, SSE & gRPC

A streams view shows WebSocket, Server-Sent Events and gRPC messages frame by frame, with timing, byte counts and decoded close codes.

Import & export

Interchange with the rest of your toolkit: HAR 1.2, Fiddler SAZ archives, Postman collections, and Ferrotap's own .ftap format.

Trusting HTTPS traffic

About the certificate. To read HTTPS, Ferrotap acts as a man-in-the-middle using its own root certificate authority. That CA is created on your machine the first time you need it, and its private key never leaves your device. There is no shared or downloadable “Ferrotap cert” to install — publishing one with a known private key would let anyone decrypt anyone's traffic. You trust your own CA, and only you hold its key.

  1. In Ferrotap, open the HTTPS / certificate settings and export your root CA (a .cer/.crt file) — or let the app install it for you if it offers to.
  2. Trust that file in your system or browser store:
    • Windows: double-click the file → Install Certificate → Local Machine → place it in Trusted Root Certification Authorities.
    • macOS: open it in Keychain Access (System keychain), then set it to Always Trust.
    • Firefox (its own store): Settings → Privacy & Security → Certificates → View Certificates → Authorities → Import, and trust it for websites.
  3. Point your system or browser proxy at Ferrotap's listener (the app shows the address), or use its system-proxy toggle.

Only trust a root CA you generated yourself, and remove it when you're done if the machine isn't solely yours.

Filter cheat sheet

Session grid — keys

host:example.com
status:5xx          # class, range 400-499, list 401,403
method:POST
size:>100000         # bytes; dur:>=2000 ms
path:/api  scheme:https  ip:1.2.3.4
type:json  header:authorization  body:error
-host:ads.com       # leading - excludes

Session grid — expression (mitmproxy-style)

~m GET & ~c 2xx
~d "api\.example\." | ~t json
~u /v1/ & ~h authorization
~b "\"error\""      # request or response body
! ~s                # not a response

Breakpoints

~q                 # request stage
~s & ~c 5xx         # failing responses
~m POST & ~u /login
~t json            # content-type
~h x-debug         # a header
~b secret          # body

Packet captures (Wireshark-style)

tcp.port == 443
ip.addr == 10.0.0.0/24
tcp.port in {80 443 8080}
http.response.code >= 400
dns.qry.name contains "api"
frame.len > 1000 && !dns
